# Лабораторная №2, вариант 20

Макеев Илья Михайлович, М8О-209БВ-25.

Найти три точки в пространстве, образующие треугольник максимальной площади.
Весь код находится в `main.c`. Комментариев в нём нет.

## Запуск

```sh
cd lab2
cc -O2 -std=c11 -Wall -Wextra -Wpedantic main.c -o lab2 -pthread -lm
./lab2 -t 10 -n 2000
```

Команды выполняются из корня репозитория. Если терминал уже открыт в `lab2`,
первую строку нужно пропустить. Вместо команды `cc` можно выполнить `make`.

`-t 10` задаёт 10 потоков, включая основной. `-n 2000` задаёт 2000 точек.
Порядок ключей фиксированный: сначала `-t`, затем `-n`.
Допускаются от 1 до 1024 потоков и от 3 до 5000 точек.

Программа сама создаёт точки по простым формулам. При одинаковом количестве точек
получается одинаковый массив. Файлового ввода в этой версии нет.
Первой строкой выводится результат последовательного поиска, второй — параллельного.
Затем выводятся ускорение и эффективность. Номера точек начинаются с 1.
При нескольких равных максимумах версии могут выбрать разные правильные тройки.

## Как устроен код

- `Point` — одна точка с координатами `x`, `y`, `z`.
- `Result` — максимальная площадь и номера трёх точек.
- `number` превращает цифры аргумента запуска в целое число.
- `area` считает площадь треугольника: половину длины векторного произведения его сторон.
- `search` перебирает все тройки `i < j < k` и запоминает лучший результат своего потока.
- В `main` сначала `p = 1`, поэтому весь поиск выполняет основной поток.
  Затем `p` равно заданному числу потоков: создаются `p - 1` дополнительных потоков,
  а основной поток тоже считает. `pthread_join` ждёт окончания каждого из них.

При двух потоках первый обрабатывает `i = 0, 2, 4, ...`, второй — `i = 1, 3, 5, ...`.
Каждый пишет в свой элемент `results`, поэтому мьютекс не нужен.
Выделение памяти через `malloc` не используется: массивы имеют заранее заданные размеры.

Для ввода-вывода используется только `printf`. Для самой лабораторной нужны
`pthread_create`, `pthread_join` и `clock_gettime`. `sqrt` выполняет математическое вычисление.
Ошибки создания и ожидания потоков, а также получения времени проверяются обычными `if`.
При ошибке программа печатает сообщение и завершается с кодом 1.

## Формулы и замеры

Ускорение `S = Ts / Tp`. Эффективность `E = S / p`.
Здесь `Ts` — время последовательного поиска, `Tp` — время параллельного,
`p` — число потоков, включая основной. Для эффективности в процентах нужно умножить `E` на 100.
Время включает создание и ожидание потоков, поиск и объединение результатов.
Создание массива точек и вывод результата выполняются вне замера.

На этом Mac 10 логических ядер. Для таблицы подходят `1, 2, 4, 8, 10, 32, 128, 1024` потоков.
Автоматическая серия измерений для новой версии:

```sh
python3 benchmark.py
```

Скрипт создаст `results-simple.json` и `results-simple.md`.
Отчёт `209_Макеев_Лаб2.docx` и `graphs.png` обновлены под текущий `main.c`
и серию измерений от 12 ноября 2026 года. Новый запуск скрипта сам Word-отчёт не изменяет.
Для работы программы и её сдачи достаточно `main.c`; отчёт сдаётся отдельно.

## Показ потоков через ОС

Запусти в первом терминале:

```sh
./lab2 -t 10 -n 5000
```

Когда появится первая строка с последовательным результатом, во втором терминале выполни:

```sh
ps -M -p "$(pgrep -x lab2)"
```

В macOS `ps -M` показывает отдельные потоки. Во время параллельного поиска их не более 10.
К концу поиска часть потоков может уже завершиться. В Linux используется `ps -L`.
Для текущей версии получены 10 строк потоков при `-t 10 -n 3000`.
Результат сохранён в `threads-simple-10.txt`, вывод программы — в `protocol-simple.txt`.
